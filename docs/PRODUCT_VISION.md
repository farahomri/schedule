DASS is an internal production scheduling system developed for Draexlmaier Tunisia.

The objective is to replace manual technician scheduling with an intelligent scheduling system.

The application must become a production-ready application.

My priority is NOT adding many features.

My priority is making the application work correctly from beginning to end especially the scheduling logic.

The application should be cleanly architected and easy to maintain.

The final application should eventually support:

- PostgreSQL
- SQLAlchemy
- Alembic
- Layered architecture
- Streamlit frontend
- Future FastAPI backend
- Future AI chatbot
- Multi-user support

The scheduling engine is the heart of the system.

Its behavior must be preserved while being refactored.

I prefer incremental refactoring instead of rewriting.

I want every architectural decision explained before implementation.

Whenever you disagree with my architecture, explain why.

Do not optimize for speed.

Optimize for correctness and maintainability.
